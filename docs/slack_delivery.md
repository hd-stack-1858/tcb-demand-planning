# Slack delivery (`automation/slack_sender.py`)

Second, parallel delivery channel alongside email (`automation/email_sender.py`)
— reports and failure/session-expiry alerts post to a Slack channel, giving
new joiners a searchable archive of past reports and a single place to see
alerts. Part of [#38](https://github.com/hd-stack-1858/tcb-demand-planning/issues/38),
under the parent migration [#32](https://github.com/hd-stack-1858/tcb-demand-planning/issues/32).

**No SMTP involved.** Slack delivery uses the Slack Web API directly over
HTTPS (bot token, no email protocol at all) — a completely separate
mechanism from `email_sender.py`. Slack's free plan is sufficient; the only
free-tier limitation is 90-day message/file history, which is an accepted
tradeoff for the "browse older reports" use case.

## Setup

1. api.slack.com/apps → **Create New App** → **Blank app** (not "AI agent" or
   "Starter app" — no interactivity is needed here, just two API calls).
2. **OAuth & Permissions** → Bot Token Scopes → add `chat:write`, `files:write`.
3. **Install to Workspace** → copy the Bot User OAuth Token (`xoxb-...`).
4. Invite the bot to the target channel: `/invite @<app name>`.
5. Get the channel ID from that channel's "View channel details" panel.
6. Set `SLACK_BOT_TOKEN` / `SLACK_CHANNEL_ID` in `.env` (see `.env.example`).

## API

```python
from automation.slack_sender import send_with_attachments, send_alert

send_with_attachments("MTD sales report", [report_path])   # file upload
send_with_attachments("plain status update", [])            # chat.postMessage only
send_alert("Blinkit Scraper — Session Expired", "Run: python automation/blinkit_auth.py")
```

Mirrors `email_sender.py`'s shape (`send_with_attachments` / `send_alert`) so
both channels can be wired into the same failure/expiry branches in
`daily_runner.py` / `fc_scraper.py`.

## Upload mechanism

Slack's old `files.upload` endpoint is deprecated. Current flow, used here:

1. `files.getUploadURLExternal` — reserve an upload slot, get a URL + `file_id`
2. `POST` the raw file bytes to that URL
3. `files.completeUploadExternal` — finalizes and shares the file to the channel

## Verification history

Proved out in three stages before being formalized as this module:
1. Local Docker → synthetic report saved locally (Docker mechanics only)
2. Local Docker → Slack (synthetic report, proved the upload flow)
3. **Real Blinkit sales report**, generated by the actual containerized
   `blinkit_scraper.py` (session loaded from Supabase `portal_sessions`),
   posted via this exact module — confirmed landing in the real channel.

Stage remaining: the same flow from a **Cloud Run** container instead of
local Docker (see [#35](https://github.com/hd-stack-1858/tcb-demand-planning/issues/35)).
